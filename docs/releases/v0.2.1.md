# ClipCraft 0.2.1

A fix release for games that ClipCraft recognized but could not record, plus better sound.

## Fixes and changes

- **Games whose window belongs to another process are recorded.** FiveM, Rockstar titles and
  Unreal games with a small bootstrap executable start a second process that owns the real game
  window. ClipCraft now looks in the processes a game starts and in other processes recognized as
  the same game, prefers the window you are looking at, and otherwise takes the largest one (even
  with an empty title). This replaces the message "found <game> running, but this desktop did not
  expose its game window".
- **A launcher or loading window closing no longer stops clipping.** When the window being recorded
  closes while the game keeps running, capture restarts on the game's new window instead of
  stopping with "the monitor or window being recorded went away".
- **New setting, on by default: record the screen when a game's window can't be found.** Instead of
  staying idle, ClipCraft records the chosen monitor as that game's session and moves to the
  game's window as soon as one appears. Turn it off in Settings → Games to keep the old behavior.
  Windows are also matched by their own process name and window class, as Vice does; on Linux
  this recognizes Proton games by their `steam_app_<id>` window class.
- **Better sound:** microphone and system sound at other sample rates are converted with a
  windowed-sinc filter (no aliasing noise), and loud mixes are turned down by a look-ahead limiter
  instead of hard clipping.
- **Recovery:** start-up recovery leaves alone a file that is still growing.

## Important limits

- The game-window changes are tested with generated windows and processes, on Linux/X11 and in a
  Windows build. They have not yet been tried with FiveM or other affected games on real Windows
  machines; please report what you see.
- The screen fallback records a whole monitor, which can include other apps.
- Downloads are unsigned. Windows may show a SmartScreen warning. Check downloads against the
  release's SHA256SUMS.txt.

No media, logs, screenshots, or bug reports are uploaded automatically.
